== งานหลัก: ประกอบเว็บตัวอย่างบนโครงมาตรฐาน GSAP ==
เว็บเราตอนนี้ใช้ engine สกรอลที่เขียนเอง (js\main.js) มันวิ่งได้ แต่อยากเห็นว่า
ถ้าย้ายไปอยู่บนโครงมาตรฐานของวงการ (GSAP ScrollTrigger + Lenis) ความรู้สึกต่างกันแค่ไหน

สร้างโฟลเดอร์ใหม่ proto-gsap\ แล้วประกอบ "เว็บตัวอย่าง" ในนั้น:
- ขอบเขต: พอร์ต "ทั้งด่านเท่าที่มีอยู่" ไม่ใช่แค่ช่วงต้น — บั๊ก scrub ชอบโผล่
  ตอนด่านมืดกับจุดกระโดด ซึ่งอยู่ช่วงกลางถึงท้าย ถ้าตัดมาแค่สองฉากจะเทียบไม่ได้
- ห้ามแก้ ห้ามลบ ไฟล์เดิมนอก proto-gsap\ แม้แต่ไฟล์เดียว (ยกเว้น .gitignore ถ้าจำเป็น)
- เอาของเดิมมาใช้ได้เต็มที่: assets\cat.png, ริกแมว 3 โหนดจาก js\cat.js
  (#catWrap → #catLean → #catSq), เลย์เอาต์ฉากจาก js\scene.js, ข้อความ beat จาก index.html
- GSAP ตอนนี้ฟรี 100% ทุกปลั๊กอิน โหลดจาก CDN:
    https://cdn.jsdelivr.net/npm/gsap@3/dist/gsap.min.js
    https://cdn.jsdelivr.net/npm/gsap@3/dist/ScrollTrigger.min.js
    https://cdn.jsdelivr.net/npm/lenis@1/dist/lenis.min.js
  (เว็บจริงค่อยตัดสินใจทีหลังว่าจะฝังหรือใช้ CDN — ตัวอย่างนี้ CDN ไปก่อน)

วิธีแมปของเดิมเข้ากับ ScrollTrigger:
- ScrollTrigger อันเดียว pin ทั้ง stage, scrub: true, end ยาวเท่า SCROLL_LEN เดิม
- progress ของ ScrollTrigger (0..1) แทนค่า cur เดิมใน main.js แล้วป้อนให้
  ระบบเดิมทั้งหมด (ตำแหน่งโลก, ท่าเดินแมว, กล้อง, ด่านมืด) ตรรกะพวกนี้ก็อปมาได้เลย
- Lenis เป็นตัวขับสกรอล ผูกกับ gsap ticker ตามสูตรทางการของ Lenis
  แต่ต้องปิดได้ด้วย query string: เปิดไฟล์ด้วย ?lenis=0 แล้ว Lenis ต้องไม่ทำงาน
  (เหลือ ScrollTrigger เพียวๆ) — จะได้แยกออกว่าความรู้สึกที่ต่างมาจากตัวไหน
- ท่าเดินแมวยังต้องผูกกับความเร็วสกรอล (ScrollTrigger.getVelocity()) ไม่ใช่เวลา

กติกาจาก CLAUDE.md ที่พลาดกันบ่อยที่สุด ย้ำอีกรอบ:
- ทุกตำแหน่งเป็น progress 0..1 ห้ามใช้พิกเซลตายตัว
- เลื่อนขึ้นทุกอย่างต้องถอยกลับเป๊ะ (scrub-safe) ห้าม one-shot trigger
- ด่านมืดห้าม invert ตัวแมว ใช้ rim drop-shadow 4 ทิศ
- ขาว-ดำล้วน มีแค่ --ink กับ --paper
- ตัดคำไทยด้วย Intl.Segmenter เท่านั้น
- ออกแบบที่ 390px ก่อนเสมอ
