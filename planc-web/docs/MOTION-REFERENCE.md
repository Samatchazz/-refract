## 1. ปัญหาใหญ่ที่สุด: เกมมี "เวลา" แต่เว็บนี้มีแค่ "ตำแหน่ง"

เทคนิคทำให้ฉากมีชีวิตเกือบทั้งหมดในโลกเกม เขียนอยู่บนสมมติฐานว่าเวลาเดินหน้าอย่างเดียว
เว็บนี้ไม่มีเวลา มีแค่ `cur` (0..1) ที่วิ่งไปกลับได้ตามนิ้วของคนดู

**ทุกเทคนิคที่ยืมมา ต้องแปลงก่อนใช้เสมอ** แปลงตามตารางนี้:

| ประเภทในเกม | แปลงเป็นอะไรในเว็บนี้ | เลื่อนกลับแล้วเป็นไง |
|---|---|---|
| **ambient ที่ไม่มีสถานะ** (ลม เมฆ ไฟกะพริบ กระพริบตา หายใจ grain) | ใช้นาฬิกาตัวเองได้เลย `performance.now()` | ไม่พัง เพราะมันไม่มีอะไรให้ย้อน |
| **สปริง / การหน่วงตาม** (หาง หู เงา กล้อง) | เก็บสปริงไว้ แต่ **เป้าหมาย**ต้องมาจาก `cur` | ไม่พัง สปริงลู่เข้าหาเป้าเสมอ เลื่อนกลับเป้าก็กลับ |
| **เหตุการณ์ที่มีอายุ** (ฝุ่น เศษ เส้นความเร็ว) | อายุ = **ระยะที่เดินเลยมา** ไม่ใช่เวลาที่ผ่านไป | ไม่พัง เพราะเป็น pure function ของ `cur` |
| **hitstop / freeze frame** | บีบ `cur` ให้เดินช้าลงในช่วงแคบๆ รอบจุดชน | ไม่พัง เพราะเป็นแค่การรีแมป `cur` |
| **flag ว่า "เกิดไปแล้ว"** | ❌ **ห้ามใช้เด็ดขาด** | พังทันที |
| `setTimeout` / `setInterval` / CSS keyframes ที่มีสถานะ | ❌ **ห้ามใช้เด็ดขาด** | พังทันที |

**สูตรแปลง "อายุ" ที่ใช้ซ้ำได้ทุกที่:**

```js
// อายุของเอฟเฟกต์ = เดินเลยจุดนั้นมากี่พิกเซลแล้ว
// LIFE_PX = เอฟเฟกต์นี้อยู่ได้กี่พิกเซลของการเดิน (ไม่ใช่กี่วินาที)
function ageAt(cur, p, travel, LIFE_PX){
  const a = (cur - p) * travel / LIFE_PX;
  return (a > 0 && a < 1) ? a : -1;        // -1 = ยังไม่เกิด หรือหมดอายุแล้ว
}
```

**ห้ามใช้ `Math.random()` ในลูปเรนเดอร์** ฝุ่นชิ้นที่ 3 ต้องอยู่ตำแหน่งเดิมเสมอ
ไม่ว่าจะเลื่อนผ่านกี่รอบ ใช้ hash จากดัชนีแทน:

```js
const rnd = i => { const s = Math.sin(i * 12.9898) * 43758.5453; return s - Math.floor(s); };
```

## 2. สี่สูตรกลาง — เขียนครั้งเดียว ใช้ทั้งฉาก

### 2.1 ลมเส้นเดียว คุมทั้งฉาก

นี่คือเทคนิคที่ให้ผลตอบแทนสูงที่สุดต่อบรรทัดโค้ด เพราะมันทำให้หญ้า ธง เมฆ หาง
และป้าย DEADLINE ดู "อยู่ในสภาพอากาศเดียวกัน" แทนที่จะต่างคนต่างขยับ

หลักการมาจากการบวกคลื่นไซน์หลายความถี่ แล้วคูณด้วยซองลมกระโชกที่ช้ากว่ามาก
ส่วน `x` (ตำแหน่งในโลก) คือตัวเลื่อนเฟส ทำให้ลมพัดเป็นระลอกจากซ้ายไปขวา
ไม่ใช่ทุกอย่างไหวพร้อมกันเหมือนโดนสั่ง

```js
// t = performance.now()/1000, x = ตำแหน่งในโลก (px)
// ลมไม่มีสถานะ → ใช้นาฬิกาตัวเองได้ ไม่ผิดกฎ scrub-safe
function wind(x, t){
  const gust = 0.55 + 0.45 * Math.sin(t * 0.19 + 1.3);      // ซองกระโชก ~33 วิ/รอบ
  return gust * (
      Math.sin(t * 0.9  + x * 0.0060) * 0.60 +               // คลื่นหลัก
      Math.sin(t * 2.3  + x * 0.0130) * 0.28 +               // ระลอกเล็ก
      Math.sin(t * 0.37 + x * 0.0021) * 0.12                 // คลื่นยาว
  );                                                          // ผลลัพธ์ ≈ -1..1
}
```

ทุกชิ้นเอา `wind()` ไปคูณด้วยแอมพลิจูดของตัวเอง: หญ้าใกล้ 1.0, เมฆ 0.3,
ธง 1.4, ป้าย DEADLINE 0.6, หางแมว 0.25 — ตัวเลขเหล่านี้เป็นจุดตั้งต้น ปรับด้วยตา

### 2.2 สปริงหน่วงพอดี (critically-damped spring)

ใช้กับทุกอย่างที่ต้อง "ตามหลัง" — หาง หู กล้อง เงา ป้าย
สูตรนี้เป็นแบบ closed-form ไม่สะสม error และไม่แกว่งเกิน มาจาก *Game Programming Gems 4*
ต่างจาก `lerp` ตรงที่มันมีความเร็วของตัวเอง จึงเลยเป้าแล้วค่อยกลับ — นั่นคือสิ่งที่ทำให้ดูมีน้ำหนัก

```js
// s = {x, v} เก็บไว้ข้ามเฟรม, dtSec = วินาทีจริง
// damp = ใช้เวลากี่วินาทีถึงจะตามทัน (0.2 คือค่าตั้งต้นที่ใช้กันทั่วไป)
function damp(s, target, dampSec, dtSec){
  const w  = 2 / dampSec;
  const e  = Math.exp(-w * dtSec);
  const ch = s.x - target;
  const tm = (s.v + ch * w) * dtSec;
  s.v = (s.v - tm * w) * e;
  s.x = target + (ch + tm) * e;
}
```

ค่าตั้งต้น: หาง `0.24` หู `0.12` ป้าย `0.30` กล้อง `0.18`
และต้องมีลิมิตองศาไม่ให้เหวี่ยงเกิน — 30° เป็นค่าที่ใช้กันทั่วไป

### 2.3 ระยะใกล้ → แรงผลัก (ใช้กับหญ้าที่โดนแมวปัด)

เทคนิคจากงาน interactive foliage ใน 2D: แปลงระยะห่างเป็นค่า -1..1
แล้วเอาไปดัดยอดของต้นหญ้า ทิศทางมาจากว่าแมวอยู่ซ้ายหรือขวาของกอนั้น

```js
const R = 96;                                  // รัศมีที่เริ่มโดนผลัก (px)
const d = (bladeX - catWorldX) / R;
// (1 - d²) ให้ขอบนุ่ม ไม่กระตุกตอนเข้า-ออก แรงสุดตอนแมวอยู่ตรงกอพอดี
const near = Math.abs(d) < 1 ? (1 - d*d) : 0;  // 0..1 เสมอ
const bend = near * dir * 34;                  // ทิศมาจาก dir องศาสูงสุดที่ยอมให้ดัด
```

⚠️ **ทิศทางต้องมาจาก `dir` (ทิศที่แมวเดิน) ห้ามมาจาก `Math.sign()` ของระยะ**
ถ้าใช้เครื่องหมายของระยะ ตอนแมวเดินผ่านกลางกอพอดี ค่าจะกระโดดจาก `+34°`
ไปเป็น `-34°` ในเฟรมเดียว หญ้าจะสะบัดกลับด้านแบบผิดธรรมชาติทุกกอที่เดินผ่าน
(ผมเขียนผิดแบบนี้ในร่างแรก จับได้ตอนไล่ตัวเลขจริง — ตรวจแล้วสูตรด้านบนต่อเนื่องดี)

**อันนี้เป็น pure function ของ `cur` โดยธรรมชาติ** เลื่อนกลับแล้วหญ้าลุกกลับเอง
ถ้าอยากได้อาการดีดกลับแบบสปริง ให้ป้อน `bend` เป็น *เป้าหมาย* ของ 2.2
อย่าไปยิงแรงกระแทกตอน "ออกจากกอ" แบบที่เกมทำ เพราะนั่นคือ event ที่ย้อนไม่ได้

### 2.4 hitstop แบบสกรอล

ในเกม จังหวะกระแทกจะหยุดเวลาไว้ 60–90ms แล้วค่อยไปต่อ — มันขายน้ำหนักได้ทั้งที่ไม่มีอะไรขยับเลย
เว็บนี้หยุดเวลาไม่ได้ (นิ้วคนดูคือเวลา) แต่ทำสิ่งเดียวกันได้ด้วยการ**บีบ `cur` ให้เดินช้าลง**
ในช่วงแคบๆ รอบจุดกระแทก แล้วคืนความเร็วหลังจากนั้น

เป็นแค่การรีแมป `cur` → `cur` ดังนั้นเลื่อนกลับก็ยังถูกต้อง

```js
// เรียกก่อนส่ง cur เข้าระบบอื่นทั้งหมด
function hitstop(cur, points, w = 0.006, hold = 0.55){
  for (const p of points){
    const d = cur - p;
    if (Math.abs(d) > w) continue;
    const t = d / w;                             // -1..1
    return p + d * (hold + (1 - hold) * t * t);  // ตรงกลางช้าที่สุด
  }
  return cur;
}
```

## 3. ตารางใหญ่ — ทุกชิ้นในฉาก ต้องขยับยังไง

ตัวเลขทั้งหมดคือจุดตั้งต้น **ต้องปรับด้วยตาจริงเสมอ** ห้ามเชื่อว่ามันถูกเพราะเขียนไว้ในนี้

### ชั้นฟ้า (`#lSky`, 0.12x)

| ชิ้น | ขยับยังไง | ขับด้วย |
|---|---|---|
| ไล่เฉดฟ้า | ค่อยๆ เข้มขึ้นตลอดด่าน แล้วเข้มสุดตอนเข้าด่านมืด | `f(cur)` ล้วน |
| ดวงจันทร์/อาทิตย์ (ยังไม่มี) | ไต่โค้งขึ้น-ลงตลอดด่าน ชั้นลึกกว่าเนิน (0.04x) | `f(cur)` ล้วน |
| เนินไกล | พารัลแลกซ์อย่างเดียว **ห้ามให้ไหวเอง** — ของไกลมากที่ขยับได้จะทำลายระยะทันที | — |
| นก (ยังไม่มี) | ฝูงนกผูกกับตำแหน่ง `p` คงที่ พอเดินใกล้ถึงจะบินขึ้น | `ageAt(cur, p, …)` |

### ชั้นกลาง (`#lMid`, 0.35x)

| ชิ้น | ขยับยังไง | ขับด้วย |
|---|---|---|
| เมฆ | มีแล้ว — เพิ่ม: ความเร็วต่างกันต่อก้อน + ลอยขึ้นลงเบาๆ ด้วย `wind()*0.3` | นาฬิกาตัวเอง |
| ไฟหน้าต่างตึก | ติด-ดับช้าๆ ไม่พร้อมกัน เฟสจากดัชนีหน้าต่าง | นาฬิกาตัวเอง |
| ป้าย/เสาอากาศบนตึก | แกว่งตาม `wind()*0.4` | นาฬิกาตัวเอง |

### ชั้นด่าน (`#lWorld`, 1.0x)

| ชิ้น | ขยับยังไง | ขับด้วย |
|---|---|---|
| พื้นอิฐ | ตัวพื้นไม่ขยับ แต่ต้องมี **ฝุ่นเด้ง** ตอนแมวลงพื้น | `ageAt()` จากจุดลงพื้น |
| **รอยเท้า** | รอยที่ค้างอยู่ข้างหลัง — เดินผ่านแล้วเห็นว่าเคยผ่านมา | `cur > ตำแหน่งรอย` |
| ขอบหลุม | หญ้าห้อยที่ปากหลุม ไหวตามลม + ไหวแรงขึ้นตอนแมวกระโดดข้าม | `wind()` + ระยะ |
| DEADLINE | หายใจ (สเกล 1.0↔1.03), ป้ายแกว่งตามลม, **สั่นตอนแมวใกล้** | นาฬิกา + ระยะ |
| บล็อก `!` | เด้ง (มีแล้ว) + ดาวกระเด็นออก + เศษกระเด็น 6 ชิ้น | `ageAt()` |
| ธงที่เสา | ไซน์ที่แอมพลิจูดเพิ่มตามระยะจากเสา — ยิ่งปลายยิ่งสะบัด | `wind()*1.4` |
| เสาธง | สั่นตามแนวยาวตอนแมวแตะ ลดลงตามระยะ | `ageAt()` |
| ข้อความ | เข้าทีละคำ (มีแล้ว) — เพิ่ม: ขาออกให้เลือนไปทางซ้าย ไม่ใช่หายวับ | `f(cur)` |

**สูตรธง** — แอมพลิจูดโตตามระยะจากเสา คือหัวใจของการทำผ้าให้ดูเป็นผ้า:

```js
// seg = 0..1 (0 = ติดเสา, 1 = ปลายธง)
const amp   = seg * seg * 14;                       // โตแบบกำลังสอง ไม่ใช่เชิงเส้น
const phase = t * 4.2 - seg * 3.1;                  // คลื่นวิ่งจากเสาไปปลาย
const y     = Math.sin(phase) * amp * (0.5 + wind(flagX, t) * 0.5);
```

### แมว

| ชิ้น | ขยับยังไง | ขับด้วย |
|---|---|---|
| ขา | เฟสตรงข้ามกัน (เฟส 3) | `phase`, `v` |
| **หาง** | ตามหลังทุกอย่าง หน่วงที่สุด + ลมเบาๆ ตอนหยุดนิ่ง | สปริง `damp 0.24` |
| **หู** | ตามหลังหัวเล็กน้อย สะบัดตอนลงพื้น | สปริง `damp 0.12` |
| หนวด | ไหวตามลม แอมพลิจูดเล็กมาก | `wind()*0.15` |
| กระพริบตา | ทุก 3–6 วิ ไม่สม่ำเสมอ | นาฬิกาตัวเอง |
| หายใจ | ตอน `v` ใกล้ 0 ตัวขยาย-หด 1.5% | นาฬิกาตัวเอง × `(1-v)` |
| เงา | มีแล้ว — เพิ่ม: จางลงเมื่อสูง (มีแล้ว) และ**เบี้ยวไปตามทิศเดิน** | `dir`, `jy` |
| ฝุ่นใต้เท้า | ออกทุกครั้งที่เท้าแตะพื้น ตอน `v` สูง | `phase` + `v` |

**หางเป็นข้อที่ให้ผลตอบแทนสูงสุดในตัวแมว** — ของที่ตามหลังคือสิ่งที่ทำให้ตัวละคร
ดูมีมวล การที่ทุกส่วนขยับพร้อมกันเป๊ะคือสาเหตุอันดับหนึ่งที่ทำให้อะไรดู "เป็นหุ่น"

### ชั้นหน้า (`#lFore`, 1.25x)

| ชิ้น | ขยับยังไง | ขับด้วย |
|---|---|---|
| **หญ้าหน้า** | ไหวตามลม **+ ถูกแมวปัดล้มตอนเดินผ่าน** | `wind()` + สูตร 2.3 |

หญ้าที่โดนปัดคือข้อที่ควรทำก่อนเพื่อนในทั้งไฟล์นี้ เพราะมันทำให้แมว
"มีอยู่จริงในฉาก" แทนที่จะเป็นภาพลอยทับฉากหลัง และมันเกิดขึ้นทุกก้าว
ไม่ใช่เกิดครั้งเดียวตอนผ่านจุดใดจุดหนึ่ง

**ข้อควรระวัง:** ตอนนี้หญ้าเป็น `background-image` ผืนเดียว ดัดทีละกอไม่ได้
ต้องเปลี่ยนเป็นกอแยกชิ้นเฉพาะช่วงที่อยู่ในจอ (~14 กอ) แล้วรีไซเคิลตำแหน่ง
อย่าสร้างหญ้าทั้ง 7,590px เป็น DOM

## 4. ความลึกในภาพขาว-ดำ

ในงานสีจะใช้ความอิ่มสีบอกระยะได้ แต่เว็บนี้ไม่มีสี เหลือเครื่องมือ 4 อย่าง
ต้องไล่ให้เป็น **บันได** ทุกชั้น อย่าไล่แค่ชั้นเดียว:

| เครื่องมือ | ไกล → ใกล้ | สถานะตอนนี้ |
|---|---|---|
| คอนทราสต์ (opacity) | .15 → .30 → 1.0 | ✅ มีแล้ว |
| ความหนาแน่นของรายละเอียด | เนิน = ก้อนเดียว → หญ้า = เห็นทีละใบ | ✅ มีแล้ว |
| ความหนาเส้น | ไกล = ไม่มีเส้นเลย ใกล้ = เส้นหนา | ❌ ยังไม่ได้ทำ |
| แอมพลิจูดการไหว | ไกลแทบไม่ไหว ใกล้ไหวชัด | ❌ ยังไม่ได้ทำ |

ข้อสุดท้ายสำคัญกว่าที่คิด — **ของไกลที่ขยับเท่าของใกล้ จะกระโดดมาอยู่ใกล้ทันที**
ในสายตาคนดู ทุกแอมพลิจูดต้องคูณด้วย depth factor ของชั้นตัวเอง

## 5. ทำอะไรก่อน (เรียงตามผลตอบแทนต่อแรง)

1. **หญ้าโดนแมวปัด** — เกิดทุกก้าว เปลี่ยนความรู้สึกทั้งเว็บ
2. **หาง + หู หน่วงตามตัว** — ถูกที่สุด ได้ผลมากที่สุดในตัวแมว
3. **ลมเส้นเดียวคุมทุกอย่าง** — ทำให้ฉากเป็นสภาพอากาศเดียวกัน
4. **ฝุ่น + รอยเท้า** — "ร่องรอยที่ค้างไว้" ทำให้โลกจำได้ว่าเราเคยผ่าน
5. **hitstop ตอนเหยียบ + แมวเด้งขึ้น** — จังหวะเดียวที่ขายน้ำหนักได้มากสุด
6. **ธงปลิว + เสาสั่น** — ปลายทางของด่าน ควรคุ้มค่าที่เดินมา
7. **นก / ไฟหน้าต่างตึก** — ทำให้ฉากหลังไม่ใช่วอลเปเปอร์
8. **grain + เส้นความเร็ว** — ชั้นบนสุด ทำท้ายสุด

ทำทีละข้อ แล้ว `node tools/shots.mjs` + `tools/rec.mjs` แล้วส่งให้ Mat ดู
ห้ามทำรวดเดียวหลายข้อ เพราะถ้ามันรู้สึกผิดจะแยกไม่ออกว่าข้อไหนผิด

## 6. งบประมาณ perf — เป้าคือมือถือ 390px

- ขยับได้แค่ `transform` กับ `opacity` เท่านั้น
- `filter: blur()` **ห้ามใช้ในลูป** ถ้าอยากได้ motion blur ใช้เงาซ้อนโปร่งแทน
- DOM ที่ขยับทุกเฟรม รวมกันไม่เกิน ~40 ชิ้น
- particle พร้อมกันไม่เกิน 12 ชิ้น กระจายตัวด้วยสูตร: มุม `2π·i/n`, ระยะ `spread·(0.45 + rnd(i)·0.55)`
- หญ้าสร้างเฉพาะที่อยู่ในจอ แล้วรีไซเคิล
- ใส่ตัวนับ fps ชั่วคราวแล้ว**วัดบนมือถือจริง** ห้ามวัดบนเดสก์ท็อปแล้วเดา

**ต้องเคารพ `prefers-reduced-motion`** การสั่นทั้งจอเป็นตัวกระตุ้นอาการเมาภาพ
ให้ปิดการสั่นกล้อง เส้นความเร็ว และ particle ทั้งหมดเมื่อผู้ใช้ตั้งค่านี้ไว้

```js
const REDUCED = matchMedia('(prefers-reduced-motion: reduce)').matches;
```

## 7. ที่ Mat ต้องเป็นคนเลือก

- **ระดับความมีชีวิต** — ทำครบทุกข้อในไฟล์นี้ฉากจะแน่นมาก อาจแย่งความสนใจจากตัวหนังสือ
  จะเอาแค่ระดับไหน
- **ฝุ่นและรอยเท้า** อยู่ค้างตลอดด่าน หรือจางหายหลังผ่านไปหน่อย
- **นกกับไฟหน้าต่างตึก** เอาไหม (เพิ่มชีวิต แต่ดึงสายตาขึ้นไปจากตัวแมว)
- **hitstop** แรงแค่ไหน แรงไปจะรู้สึกเหมือนเว็บค้าง

เสนอเป็นตัวอย่างเทียบกันให้ดูก่อน แล้วถาม อย่าตัดสินใจแทน
